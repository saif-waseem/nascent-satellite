# الباقات والترخيص (Tiers & Licensing)

---

## 1. الباقات الأربع

| | **A — محلية** | **B — شبكة داخلية** | **C — شبكة + نسخ سحابي** | **D — مزامنة لحظية** |
|---|---|---|---|---|
| التخزين | SQLite محلي | SQLite + مضيف LAN | = B | SQLite + سحابة |
| عدد الأجهزة | **1** | 2–8 (هواتف + حواسيب) | 2–8 | غير محدود (حسب السعر) |
| يحتاج إنترنت | لا | لا | فقط وقت الرفع | لا للبيع، نعم للمزامنة البعيدة |
| النسخ الاحتياطي | ملف يدوي/مجدول | ملف يدوي/مجدول | **سحابي تلقائي يومي** | مستمر + سحابي |
| متابعة عن بُعد | ✕ | ✕ | ✕ | **✓ لوحة `dash`** |
| فروع متعددة | ✕ | ✕ | ✕ | **✓** |
| نموذج البيع | ترخيص لمرة واحدة | لمرة واحدة (حسب عدد الأجهزة) | لمرة واحدة + شهري صغير | شهري لكل جهاز/فرع |
| تكلفتك التشغيلية | **صفر** | **صفر** | سنتات/متجر/شهر (تخزين بارد) | خادم + نطاق ترددي |

### ملاحظات على التغليف
- **B وC نفس الكود تماماً.** C = B + خدمة رفع. لا تبنِ مساراً منفصلاً.
- **D تشمل LAN تلقائياً** — عند انقطاع الإنترنت تستمر الأجهزة بالمزامنة داخلياً ثم تصالح السحابة. هذه أقوى نقطة بيع لديك أمام أي منافس سحابي بحت: *"البيع لا يتوقف حتى لو انقطع الإنترنت يومين."*
- **الترقية بين الباقات لا تنقل بيانات.** A→B = تعيين الجهاز مضيفاً وإقران الأجهزة. B→C = تفعيل الرفع. C→D = تسجيل المتجر في السحابة ورفع أول لقطة. لأن قاعدة البيانات واحدة في كل الحالات.

### عن التسعير
لا أعرف سوق الديوانية/العراق بما يكفي لأعطيك أرقاماً، لكن البنية التي أنصح بها:
- **A:** رسم لمرة واحدة → يدخل نقداً فوراً ويمول التطوير.
- **B:** رسم لمرة واحدة أعلى + رسم لكل جهاز إضافي.
- **C:** رسم B + اشتراك شهري صغير يغطي التخزين بهامش.
- **D:** شهري فقط — وهنا يكون "رمزياً" منطقياً لأنك تريد حجماً كبيراً وعائداً متكرراً.
- **قاعدة:** اجعل تكلفتك التشغيلية لكل متجر معروفة بالدينار قبل أن تسعّر C وD. A وB تكلفتهما صفر، فهامشهما 100%.

## 2. تصميم الترخيص

### 2.1 ملف الترخيص
ملف نصي موقَّع بـ **Ed25519**. المفتاح الخاص عندك فقط (سكربت توليد على جهازك أو خادم بسيط). المفتاح العام مدفون في التطبيق.

```jsonc
{
  "lic_id": "01J9...",
  "store_id": "01J8...",
  "store_name": "دار لندن",
  "tier": "C",
  "device_limit": 4,
  "features": ["lan_sync", "cloud_backup"],
  "issued_at": 1758000000000,
  "expires_at": 1789536000000,
  "grace_days": 14,
  "bound_devices": ["sha256:ab12...", "sha256:cd34..."]
}
```
التوقيع في سطر منفصل (base64). التحقق offline بالكامل — لا يحتاج إنترنت.

### 2.2 بصمة الجهاز
`device_info_plus` →
- Windows: `deviceId` / Machine GUID
- Android: `id` + `board` + `fingerprint` (مجموعة، لأن كلاً منها وحده متغيّر)
- macOS: `systemGUID`

احفظ `sha256(fingerprint + salt)` فقط. **لا تعتمد على عنصر واحد** — تحديث نظام قد يغيّره ويقفل الزبون. اسمح بفرق عنصر واحد من ثلاثة.

### 2.3 بوابات الميزات (Feature Flags) — وليس فحص الباقة

```dart
// pos_licensing
class Features {
  final bool lanSync, cloudBackup, cloudRealtime, remoteDashboard, multiBranch;
  final int deviceLimit;
}

@riverpod
Features features(Ref ref) => ref.watch(licenseProvider).features;
```

في الـ UI:
```dart
// ✅ صحيح
if (ref.watch(featuresProvider).cloudBackup) const BackupSettingsTile(),

// ❌ خطأ — لا تفحص الباقة أبداً
if (license.tier == 'C') ...
```
السبب: بعد ستة أشهر ستبيع "إضافة التقارير المتقدمة" لزبون في الباقة B. مع الأعلام تضيف علماً واحداً؛ مع فحص الباقة تعيد كتابة عشرات الشروط.

### 2.4 قاعدة فترة السماح (الأهم تجارياً)

**لا تُوقف متجراً عن البيع أبداً.**

| الحالة | السلوك |
|---|---|
| ترخيص صالح | كل شيء يعمل |
| منتهٍ، ضمن `grace_days` | يعمل كاملاً + شريط أصفر "انتهى الاشتراك — تبقى N يوم" |
| منتهٍ، بعد فترة السماح | **البيع يستمر محلياً** (تهبط فعلياً إلى باقة A) + تتوقف المزامنة والنسخ السحابي + شريط أحمر |
| فشل التحقق الشبكي (D/C) | استمر بآخر ترخيص معروف حتى 14 يوماً. عطل الشبكة ليس عدم دفع |

متجر مغلق بسببك = زبون خسرته للأبد + سمعة سيئة في سوق صغير. المتجر الذي يعمل مع شريط أحمر مزعج يدفع.

### 2.5 فرض حد الأجهزة
يُفرض عند **الإقران** (المضيف يرفض الجهاز رقم N+1 برسالة واضحة)، لا عند كل تشغيل. في الباقة A: التحقق بمطابقة البصمة عند الإقلاع.
اجعل "فكّ ارتباط جهاز" متاحاً للتاجر بنفسه — لا تجبره على الاتصال بك عند تبديل هاتف.

### 2.6 هيكل حزمة `pos_licensing`
```
pos_licensing/
  license_payload.dart      (Freezed)
  license_verifier.dart     (Ed25519 verify)
  device_fingerprint.dart
  license_store.dart        (secure storage + نسخة في SQLite)
  features.dart
  license_controller.dart   (Riverpod: load → verify → grace → features)
  tier_defaults.dart        (خريطة tier → features الافتراضية)
```

## 3. مصفوفة القرار: ما الذي يفعله كل Transport لكل باقة

| الباقة | Transport | خدمات خلفية تعمل |
|---|---|---|
| A | `NoopTransport` | مهمة نسخ محلي مجدولة فقط |
| B | مضيف: `LanHostTransport` / قرين: `LanPeerTransport` | mDNS + WS server (المضيف) |
| C | = B | + `BackupUploader` (يومي، على المضيف فقط) |
| D | `CompositeTransport([Lan, Cloud])` | + WS سحابي + رفع تجميعات اللوحة |

اختيار الـ Transport يحدث في مكان **واحد** فقط:
```dart
@riverpod
SyncTransport syncTransport(Ref ref) {
  final f = ref.watch(featuresProvider);
  final isHost = ref.watch(deviceRoleProvider) == DeviceRole.host;
  if (f.cloudRealtime) return CompositeTransport([_lan(ref, isHost), CloudTransport(...)]);
  if (f.lanSync)       return _lan(ref, isHost);
  return const NoopTransport();
}
```
هذه الدالة هي كامل "نظام الاشتراكات" على مستوى الكود. كل شيء آخر يبقى جاهلاً بالباقة.
